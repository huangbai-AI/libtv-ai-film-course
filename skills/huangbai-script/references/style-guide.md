# 黄白写稿风格指南

## 样本范围

本指南基于飞书知识库中标题带 ✅ 的内容整理。共筛到 11 个节点，其中 8 篇属于完整口播脚本，覆盖即梦 SD 2.5、蚂蚁灵波、ChatCut、可灵、Updream、AnySearch、Seko、万镜一刻；2 篇是纯提示词，1 篇为空，不把它们作为口吻统计样本。

## 经典结构：结果钩子 → 教学承诺 → 身份 → 三步教学 → 资源互动

### 1. 先给结果

开头不解释背景，先让观众看到“AI 到底做成了什么”。结果要具体、可视化，最好带时间、数量、前后差异或出乎意料的成品。

常见入口：

| 类型 | 核心写法 | 适用场景 |
|---|---|---|
| 成果宣言 | 直接说“我做出了什么” | 自建项目、工作流、可见成品 |
| 新品事件 | 先宣布关键更新，再马上展示变化 | 新模型、新版本、发布类合作 |
| 数据冲击 | 用真实、可核验的数据说明现象 | 爆款案例、效率或效果对比 |
| 否定反转 | “这不是 A，而是 B” | 纠正旧认知、建立新概念 |
| 纠错打击 | 先指出大家常用的方法为什么没用 | 技巧教学、提示词优化 |
| 痛点危机 | 某个职业或流程突然被 AI 改变 | 行业变化、工作方式升级 |
| 意外制作 | 把复杂效果做成简单、可复用的方法 | Skill、自动化、工作台 |

前 3 秒优先只给最强画面，不急着讲过程。需要增强停留时，可以在主钩子后再放一个具体、真实、略猎奇的小案例形成“钩中钩”。数据必须可核验，不能为了冲击力编数字。

### 2. 降低门槛并给承诺

钩子后立刻回答“这和我有什么关系、难不难”。常用说法是“过程非常简单”“一分钟教会你”“看完就能学会”。承诺必须与正文一致，不空喊。

### 3. 身份句放在钩子后

固定句：“我是黄白，一个很会玩 AI 的设计师。”

这句话负责建立人物记忆，不负责抓住第一秒，因此不要放在开头第一句。一般位于效果展示和教学承诺之后。

### 4. 正文优先三段式

主结构通常是“首先 → 接着/然后 → 最后”。每一段不是功能列表，而是一个完整小闭环：

1. 我做了什么；
2. 画面上出现了什么结果；
3. 为什么有效或哪里要注意；
4. 这能给观众省什么、解决什么。

常见内容顺序：

- 第一段：找到入口、安装或建立基础设置，先把门槛降下来。
- 第二段：完成核心任务，用案例证明结果。
- 第三段：进阶玩法、自动化、复用、分享或形成 Skill。

正文经常使用对比教学：先指出普通做法为什么不够，再给更具体的正确动作。例如“不是只写高清就可以”，而是要补充镜头、材质、光线或动作等能被模型执行的信息。

60 秒到 3 分钟的视频可以粗略按以下比例控制：钩子约占 10%—25%，教学主体约占 40%—60%，结尾约占 5%—10%，其余留给身份、过渡和案例。比例只用于避免头重脚轻，不要牺牲自然节奏。

口播以短句为主，单句通常控制在 20 字左右；一句对应一个主要画面动作。复杂信息允许更长，但要在自然停顿处拆开。画面不仅写“录屏”，还要写明高亮位置、人物是否出镜、手势、词卡、前后对比，以及能否回调前面出现过的道具或画面。

精简是硬要求。一个意思只说一次，不用不同说法重复解释；动作和结果已经可见时，不再补一段抽象总结。初稿完成后必须再删一轮，删除后不影响事实、逻辑、合作要求和观众理解的句子全部删掉。

通用自媒体视频的三列表格必须按口播节拍拆行：“内容”列每行一句，最多两句紧密相连的短句；“画面说明”与口播逐行对应。同一阶段覆盖多行时，“阶段”列纵向合并为一个单元格，在飞书富表格中使用 `rowspan`，后续行不重复阶段名。禁止把整个阶段的多段口播堆进一个内容单元格。LibTV AI 影视课程的细化逐字稿不使用本三列格式，必须改读 `course-script-structure.md` 并按六列交付。

### 5. 可选彩蛋

当主体教学结束后仍有一个确实好用的取巧方法，可以用“我还有一个邪修方法”包装为压轴彩蛋。它必须带来新的操作价值，不能只是为了复现口头禅。没有合适玩法时直接省略。

### 6. 结尾三件套

1. 回扣价值：省了什么时间、解决了什么问题，或补一句真实的个人感受。
2. 资源去向：把案例、提示词、素材或文字版放进文档。
3. 互动与关注：“评论区见”“关注我，主页更多 AI 玩法”，需要时补“我们下期见”。

文档不是附属品，而是内容闭环：视频负责建立兴趣和教关键动作，文档承接复杂信息，也给评论区一个自然互动理由。

## 高频表达与作用

以下为 8 篇完整口播样本中的粗略出现次数，用于判断权重，不要求逐字复刻：

| 表达 | 次数 | 作用 |
|---|---:|---|
| 关注我 | 15 | 稳定收尾动作 |
| 主页更多 AI 玩法（含空格差异） | 13 | 固定栏目心智 |
| 文档 | 19 | 承接资料和评论互动 |
| 最后 | 24 | 教程主层级与收束 |
| 首先 | 10 | 开启第一步 |
| 然后 | 7 | 推进操作 |
| 所以 | 8 | 把功能落到结论 |
| 不过 | 8 | 增加真实感和限制条件 |
| 但是 | 7 | 制造反差或纠正误区 |
| 只需/只需要 | 13 | 降低操作门槛 |
| 我是黄白 | 9 | 人物识别 |
| 一个很会玩 AI 的设计师 | 7 | 固定身份标签 |
| 评论区 | 3 | 资源领取和互动 |
| 需要的自取 | 3 | 轻量资源引导 |

可以稳定保留：

- “我是黄白，一个很会玩 AI 的设计师。”
- “关注我，主页更多 AI 玩法。”
- “本期全部案例和提示词，我也整理到了文档里。”
- “需要的自取，我们评论区见。”

不要机械复读。围绕具体项目替换“案例、提示词、素材、网址、文字版”等名词。

补充句式库：

- 教学动作：“首先来到……”“在这里点击……”“然后搜索……”
- 简单收束：“就可以……了”“这样就非常方便了”
- 体验抛点：“让我很惊喜的是……”“还有一个很有趣的点”“就像这样”
- 递进：“当你以为这已经很不错了，接下来的才是硬菜。”
- 对比：“不是……而是……”

“就……了”可以帮助步骤显得轻，但一期不要连续重复太多次。“真的、一键、轻松、直接”等词必须有画面或操作支撑。

## 语言习惯

- 使用第一人称实操：“我做了一个”“我把它做成了”“我试了一下”。
- 直接对观众说“你”，让教学像朋友演示，而不是课堂讲义。
- 多用短句和指示词：“这个、这里、这样、就”。
- 一个观点只保留最有力的一句，不换词复述，不补“正确但没信息”的废话。
- 先说动作，再解释原理；技术信息只保留到足够完成任务的程度。
- 喜欢具体数字和可见结果，例如几秒、几个步骤、一个网站、一份文档。
- 经常用“不过、但是”补充边界，让内容不显得无脑吹捧。
- 经常把 AI 比作实习生、同事或演员，使抽象能力变成职业场景。
- 每讲一个新能力，尽快给实际案例，而不是连续堆形容词。
- 把参数翻译成人的体感，例如把帧率写成“和我平时打游戏一样流畅”，把素材数量写成画面上能看见的差异。
- 技术点后可以接一句短情绪反应，让信息有喘气点；不要连续三句只讲参数。
- 保持“兴奋地分享新玩具”的小得意，不端专家架子，也不故意谦虚客套。

## 幽默类型

黄白的幽默不是连续讲段子，而是认真教学时突然出现的一句轻反应。

### 克制自嘲

把自己放回真实从业者处境，例如“哎，自己卷自己吧”“我当年找工作哪有这个条件”。它让新工具的冲击更有人味。

### 可控夸张

用一句略夸张的判断提高记忆点，例如“看完太奶都能学会”“这回轮到我们 AI 博主的天塌了”。说完马上进入事实或步骤，不继续夸张。

### 圈内黑话

偶尔使用“邪修方法”“老朋友”“船新版本”，营造熟人感。一次只选一个，不把整篇写成网络梗合集。

### 职业类比

把 Agent 说成“很聪明的实习生”，自己像“总监”，既解释关系，也顺便制造幽默。这类幽默最适合教学内容。

### 结果后的短反应

展示成果后只补一句：“这一刻就一个字：爽。”“性价比，绝了！”短而有停顿，不再解释笑点。

### 一本正经的荒诞

人物面对荒唐处境仍然认真，笑点来自逻辑和情境，不来自挤眉弄眼或主动提醒观众“这里很好笑”。这是黄白式幽默最重要的底层规则。

### 言行反差与视觉回调

可以轻描淡写地说“我不想讲这些参数”，画面却快速掠过关键变化；也可以让上一段出现的道具、词卡或表情在后文再次出现。反差和回调必须帮助表达卖点或结构，不能靠误导观众制造笑点。

### 使用上限

- 每个大阶段最多一个轻幽默点。
- 90 秒脚本通常 1—3 个幽默点即可。
- 优先选自嘲、职业类比和结果反应；谨慎使用热梗。
- 幽默不能破坏可信度，不能取笑用户，也不能遮住操作步骤。

## 商单植入方式

把品牌放进真实工作流中的一个关键节点：先说正在完成什么任务，再自然展示产品如何减少操作或补上能力，随后回到整个工作流。品牌卖点必须转译成具体结果，如“走路时也能把选题写进库里”，而不是逐条念功能。

商单篇幅由故事需要决定。除非用户明确要求，不要在开头直接报品牌，不要每个阶段都强行出现产品，也不要用“颠覆、重新定义、行业天花板”等空泛广告词。

优先使用以下植入方式：

1. 教程就是广告：成片或工作流本身就是产品做出的结果。
2. 品牌长在动作里：“在某产品里点击某功能”，观众跟着操作即可体验卖点。
3. 痛点先于解法：先展示真实失败或限制，再让产品补上缺口。
4. 参数变成体感：用旧与新、前与后、慢与快的画面对比解释卖点。
5. 小翻车换信任：承认第一次结果不理想，再展示如何调整；不要伪造失败。
6. 不点名踩竞品：只讲旧方法或通用做法的限制，不攻击具体对象。
7. 品牌连接个人资产：把产品案例沉淀为自己的 Skill、文档、开源项目或模板，前提是这些资源确实存在。
8. 价格、排名、奖项和用户数据只在 brief 或可靠资料支持时使用，并写成对观众有意义的结果。

写商单时先列出品牌方必审元素，再给每一项寻找“教学步骤、真实案例或个人体验”的载体。先写钩子和结尾，再填中间，避免为了塞卖点破坏结构。

## 通用视频默认输出格式

| 阶段 | 内容（口播文案） | 画面说明参考 |
|---|---|---|
| 开头钩子 | 可直接念的短句 | 成品先出、对比画面、人物反应或大字字幕 |
| 身份与承诺 | 教学承诺和身份句 | 正面口播、工具或结果作背景 |
| 第一步 | 行动、结果、解释、收益 | 实拍动作和屏幕录制交替 |
| 第二步 | 行动、结果、解释、收益 | 案例前后对比、重点框选 |
| 第三步 | 行动、结果、解释、收益 | 进阶玩法、自动化或复用展示 |
| 结尾 | 价值回扣、文档互动、关注引导 | 文档缩略图、评论区指向、账号页 |

若用户要求“大纲”，压缩每格内容；若用户要求“完整脚本”，按口播节拍拆成独立表格行。每行只放一句，最多两句紧密相连的短句；同一阶段的“阶段”单元格按实际行数纵向合并。

本节只适用于普通自媒体视频。LibTV AI 影视课程的主文档只维护大纲；下挂细化脚本固定使用“阶段｜大纲｜内容｜口播｜截图｜备注”，完整规则见 `course-script-structure.md`。
