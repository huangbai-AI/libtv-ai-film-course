# LibTV 课程写稿

## 边界

- 只处理 LibTV AI 影视课程，不把课程脚本套入个人自媒体写稿结构。
- 不读取或继承 `huangbai-script` 的钩子、固定身份句、个人口吻、三列表格和自媒体结尾，除非用户明确要求组合两个 Skill。
- 课程资料不足时保留待核对项，不编造模型能力、操作步骤、品牌权益或课程事实。

## 开始前

1. 每次处理课程大纲、细化脚本或逐字稿，都完整阅读 [references/document-structure.md](references/document-structure.md)。
2. 涉及 LibTV 功能、模型、按钮、操作步骤或限制时，从已接入的《LibTV使用指南》官方文档知识库读取对应章节；只取当前课节需要的范围。
3. 开发 Cortex 写稿模块、保存中间数据或自动校验时，再读取 [references/course-script-schema.json](references/course-script-schema.json)。
4. 操作飞书知识库和文档时，同时使用 `lark-wiki` 与 `lark-doc`，先读取定位，再执行用户要求的写入。

## 先判断文档层级

1. **总文档／总目录**：只维护课程目录、课节顺序和每节入口。
2. **每节主文档／课程大纲**：每个子文档对应一节，只承载该节大纲，不是逐字稿。
3. **细化脚本／逐字稿**：下挂在对应的每节主文档下面，逐句口播只写在这里。

禁止把三个层级压平，禁止把逐字稿直接写入总目录或每节主文档。

## 任务路由

### 撰写或修改大纲

1. 定位第二级的每节主文档。
2. 维护阶段、大纲、内容及其顺序和粒度。
3. 不在主文档中展开逐句口播。
4. 大纲发生变化后，标记对应细化脚本需要重新对齐；不要静默保留已经失配的旧结构。

### 撰写或修改细化脚本

1. 先读取该节父级主文档的完整大纲。
2. 按父级顺序提取每个 `阶段 + 大纲 + 内容` 组合。
3. 把这三列视为受保护字段，逐字复制到细化脚本，不概括、改名、重排或新增结构。
4. 只围绕每个“内容”撰写口播；每句话拆成一张独立表格行。
5. 为每行口播填写一条独立截图、录屏或 B-roll。
6. 备注按需填写，可以为空。
7. 按实际口播行数纵向合并阶段、大纲和内容。
8. 写回后重新读取目标表格并校验。

### 审查现有细化脚本

1. 比较父级主文档与细化脚本中的阶段、大纲、内容。
2. 报告任何缺失、改名、重排、拆分或合并不一致。
3. 检查一句口播是否独占一行。
4. 检查每行口播是否有独立、可执行的截图/B-roll。
5. 检查纵向合并行数是否与真实口播行数一致。
6. 未获用户修改授权时只报告问题，不写回文档。

### 按飞书评论回改

1. 读取细化脚本上的飞书评论，保留评论与具体口播单元格的对应关系。
2. 合并重复评论，按功能事实、课程逻辑、口播表达、AI 味分类；先处理会影响整段的高优先级问题。
3. 只在评论授权范围内修改口播、截图或备注；阶段、大纲和内容需要变化时，先回到父级主文档修改并重新同步。
4. 评论冲突、证据不足或会改变课程观点时交给黄白判断，不自行选择。
5. 每条评论回复修改结果；未修改时写清原因。回改后重新通读上下文，并重新生成对应试听。

### 处理罗永浩课程表达

1. 只处理 LibTV 课程项目定义的罗永浩表达要求，不调用黄白个人自媒体写稿 Skill。
2. 只修改口播列，不改变阶段、大纲、内容、功能事实、案例、数据和操作步骤。
3. 优先调整句长、停顿、转折、重音和口语节奏，不凭空增加口头禅、段子、观点或未经授权的个人经历。
4. 风格处理完成后，必须进入终稿差异检查并重新生成试听。

### 终稿差异检查

1. 对比进入最终润色前的基准版本与候选终稿。
2. 确认阶段、大纲、内容和截图未被越界修改；功能、案例、数据、操作步骤和课程观点保持一致。
3. 输出逐条修改清单，写明原句、改后句和修改原因。
4. 发现越界变化时阻止锁稿并退回对应节点；只有轻微口语、错别字、语病和标点调整可以直接通过。

## 六列硬约束

固定列名和顺序：

| 阶段 | 大纲 | 内容 | 口播 | 截图 | 备注 |
|---|---|---|---|---|---|

- 不得改名、增删或调序。
- 阶段、大纲、内容必须与父级主文档完全对应。
- 一个内容单元格可以对应多行口播，但每句话必须独占一个口播单元格。
- 每行口播必须独立对应一个截图、录屏、B-roll 或其他可执行画面。
- 备注可写可不写，不用无信息占位词填满空白。
- 不用 `<br>` 在一个单元格中伪造多行口播。

## 写稿要求

- 把父级“内容”完整转译成可直接朗读的课程讲解，不遗漏该内容要求的知识点和动作。
- 保持自然、清楚、可教学的口语；一句只承担一个主要信息或动作。
- 操作类口播先明确当前界面或对象，再说动作和结果，避免无法配画面的抽象说明。
- 截图列写到可执行程度：具体界面、点击位置、参数高亮、生成结果、前后对比、讲师出镜或字幕卡。
- 发现术语、模型名或步骤存疑时写入备注并标记待核对，不在口播中猜测。

## 参考资料边界

- 《LibTV使用指南》就是已接入、可直接读取的官方文档知识库，是核对产品功能、模型、按钮、操作步骤和限制的正式来源。
- 自动检索、变更提醒和版本追踪属于后续增强能力；这些能力未完成不影响当前按章节读取和引用官方指南。
- 课程合作总文档是目标课程结构的来源。
- 影视飓风 AI 课逐字稿总目录是课程表达参考的正式入口；先按当前 LibTV 课节主题选择最相关的一至两篇，不把整套逐字稿一次性塞进写稿上下文。
- 影视飓风逐字稿只用于参考课程表达、节奏、教学展开和逐句拆分，不复制原句、个人表达、大纲结构或三列表格作为交付结构。

资料入口和详细字段规则见 [references/document-structure.md](references/document-structure.md)。

## 写回飞书

- 用户要求写入飞书时，先确认目标是第二级大纲还是第三级细化脚本。
- 细化脚本写入前必须读取父级大纲；只修改用户授权范围内的字段和行。
- 优先更新明确的目标章节或表格，不覆盖整篇文档。
- 写入后重新读取对应章节，核对六列、文本完整性、逐行画面和纵向合并。

## 交付前检查

- 是否定位到正确课节和正确层级？
- 是否恰好使用六列并保持固定顺序？
- 阶段、大纲、内容是否与父级逐字、顺序、粒度一致？
- 父级每个内容是否至少对应一行口播？
- 每句话是否独占一行口播？
- 每行口播是否都有独立截图/B-roll？
- 纵向合并是否覆盖正确的真实行数？
- 是否误用了黄白自媒体写稿规则或影视飓风三列格式？
- 是否保留了所有待核对信息，没有编造事实？
- 飞书评论是否逐条处理、回复并保留冲突升级记录？
- 罗永浩课程表达处理是否只改口播，没有新增事实、案例、观点或口头禅？
- 终稿差异检查是否确认受保护字段和课程事实没有越界变化？
