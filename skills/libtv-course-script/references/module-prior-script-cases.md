## 已形成的项目写法

### 导学课

- 用成片或明确结果建立课程价值。
- 讲清适合人群、学习成果、课程路线和跟练方式。
- 不在导学阶段过早展开工具细节。

### 画布与节点

- 用同一案例串联文字、图片、视频、版本和导出。
- 每讲一个概念，立即用操作和结果验证。
- 强调工作流结构与可复用经验，不让学员只记按钮位置。

### 生成与提示词

- 先讲输入、参考素材、模型和参数分别控制什么，再进入提示词细化。
- 提示词服务于画面目标和判断，不把术语数量当成质量。
- 对比生成结果时写清差异、选择理由和下一步修改。

### 进阶功能与案例课

- 一个高级功能对应一个可见任务，不把多个亮点堆成无主线展示。
- 案例要覆盖创意、素材、生成、筛选、声音、剪辑和交付中的真实取舍。
- 保留失败版本与成本意识，避免把生成描述成一次成功。

## 使用旧稿的规则

1. 先读当前课节父级主文档，再读最接近的一至两篇旧稿。
2. 提取术语、案例状态、已确认观点、课程承接和制作约束。
3. 旧稿中的额外列、临时列和历史修改列只用于理解过程，新稿必须回到六列终稿格式。
4. 旧稿与官方指南冲突时，以当前官方事实和已确认的产品状态为准。
5. 旧稿仍在“修改中”时，不把其中未确认表达当作锁定事实。

## 更新本模块

- 新增课节时追加主文档链接；出现下挂细化脚本后补充第三级链接。
- 课节锁稿、改名或废弃时更新状态，不删除历史入口，除非链接已经失效。
- 每次较大更新后重新提炼“已形成的项目写法”，但不把单个偶然写法升级为全局规则。
- 更新案例模块时，不连带修改官方教程、专业方法或表达模块。
