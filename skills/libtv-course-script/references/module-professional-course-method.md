## 值得吸收的方法

### 1. 把复杂技术变成连续的小胜利

- 先降低学习阻力，再建立生成方式地图。
- 先完成简单、可见的结果，再提高控制力。
- 先练单点能力，再进入完整项目。
- 每节结束都让学员留下一个作品、参数记录或可复用方法。

### 2. 结果先行，但不只展示成功

- 开头先让学员看见最终效果，知道为什么值得学。
- 操作中逐步呈现中间结果，让每一步都有反馈。
- 同时展示失败表现、原因判断和修改顺序，避免把生成过程包装得过度顺滑。

### 3. 用真实任务串联功能

- 用广告、角色、镜头、转场、动画或完整短片等任务承载工具知识。
- 功能只在任务需要时出现，不为了覆盖按钮而硬讲。
- 同一案例尽量贯穿原理、操作、结果、对比和练习。

### 4. 把抽象概念压缩成可记忆的判断结构

- 公式用于帮助新手记忆，不代替真实判断。
- 讲完简化结构后，立刻用正反例说明边界。
- 让学员知道什么时候适用、什么时候需要换方法。

### 5. 教选择与取舍

- 模型不只比较“谁最好”，还比较任务匹配、稳定性、速度、成本和后期压力。
- 提示词不只讲写法，还讲参考素材、构图、动作和模型选择的权重关系。
- 生成结果最终服务于故事、情绪和交付目标，而不是服务于参数本身。

### 6. 把练习做成闭环

- 为每节准备原始素材、提示词、参数截图、完成示例、常见错误和检查清单。
- 学员看完即可练，练完即可自查。
- 课程结尾把本节能力连接到下一节，而不是只做口号式预告。

## 对 LibTV 课程的加强项

参考课程仍有平台绑定重、成功过程偏顺滑、营销打断教学、高级技巧多但统一项目不足等问题。LibTV 课程应补足：

1. 把稳定原理和易变操作分开，减少界面改版导致整节过期。
2. 把失败诊断正式写进正课，明确“表现 → 原因 → 优先修改项 → 停止条件”。
3. 增加同任务对比实验，让模型、提示词、参考素材和参数的差异可见。
4. 用一个贯穿全课的项目收束创意、脚本、分镜、生成、筛选、声音、剪辑和交付。
5. 为结果建立验收标准，不用“看起来不错”代替判断。

## 原创性隔离规则

以下内容禁止进入 LibTV 成稿：

- 参考课程的原句或只替换少量词语的近似句。
- 能让人一眼识别来源的比喻、笑话、口头禅和转场。
- 参考课程特有的案例人物、故事设定、平台包装和营销表达。
- 为了“像”而复刻其段落顺序、章节标题或整节编排。

允许吸收的是功能层方法，例如“先展示结果”“同一任务做模型对比”“公开失败迭代”。每次使用这些方法时，都要重新根据 LibTV 当前课节的目标、案例、功能和学员任务生成结构与表达。

## 写稿时的选择方式

1. 先写本节要解决的问题和交付结果。
2. 从本模块只选择两到四个最有用的方法。
3. 用 LibTV 官方事实和项目案例重新组织课程。
4. 完稿后反向检查：去掉产品名后，是否仍像参考课程的复述？若是，重写案例、顺序和讲法。
